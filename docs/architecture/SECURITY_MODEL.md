# Security model

IRIS V0 is a same-user, machine-local runtime. Its HTTP and MCP listener binds only to `127.0.0.1`; non-loopback bind addresses are not accepted. Host-header validation rejects DNS-rebinding names, browser requests with a non-loopback `Origin` are rejected, cross-site Fetch Metadata is rejected, mutation requests require `application/json`, and request bodies are bounded.

Runtime authority is independent from TCP port selection. A contender writes and syncs a private claim file and uses an atomic hard-link to publish `authority/owner.lock`; the publication cannot replace an existing owner. The durable owner record contains the full logical/process identity, not only a PID. A live owner denies acquisition; unreadable, partial, symlinked, or ambiguous ownership fails closed. Stale recovery isolates the exact owner record and removes it only after identity reverification and a second proof that the recorded PID is absent. Authority probes are observational and do not acquire, repair, release, or advance ownership.

The runtime data root is physically canonicalized, must be outside the source checkout, must be owned by the current user, and must not grant group or other access. Foundation JSON publications use private files and atomic replacement. Endpoint metadata is accepted only when identity fields are structurally valid and API/MCP URLs share the same IPv4-loopback origin.

Project registration is explicit. Input paths must be absolute, contain no NUL byte, resolve through `realpath`, and identify an existing non-root directory. V0 stores only the canonical path and does not scan or expose project contents. Session current-project state is isolated in memory; the default project is the only project selection persisted machine-wide. Session read/update/delete requests require the owning `clientId`.

The V0 local API has no OAuth because remote access is not implemented. Local processes running as the same OS user remain inside the V0 trust boundary. PID reuse is handled conservatively: an apparently live PID prevents stale takeover, and STOP_COMPLETE refuses success until the target PID is absent, the exact endpoint descriptor is gone, and authority is unowned. Stronger per-request local authentication and OS-level process-start attestation are deferred security hardening, not claims of the V0 foundation.
