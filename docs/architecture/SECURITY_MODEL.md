# Security model

IRIS V1.3 is a same-user, machine-local runtime. Its HTTP and MCP listener binds only to `127.0.0.1`; non-loopback bind addresses are not accepted. Host-header validation rejects DNS-rebinding names, browser requests with a non-loopback `Origin` are rejected, cross-site Fetch Metadata is rejected, mutation requests require `application/json`, and request bodies are bounded.

Runtime authority is independent from TCP port selection. A contender writes and syncs a private claim file and uses an atomic hard-link to publish `authority/owner.lock`; publication cannot replace an existing owner. The owner record contains the full runtime/process identity plus a private macOS process-start marker. A live matching process denies acquisition; a reused PID with a different start marker is stale; unreadable, partial, symlinked, redirected-parent, or otherwise ambiguous ownership fails closed. Stale recovery isolates the exact record and rechecks process identity before removal. Authority probes are observational and do not acquire, repair, release, or advance ownership.

Runtime shutdown does not send `SIGTERM` to a PID chosen from stale metadata. The daemon publishes a private `control.json` with an instance-bound random credential before the public endpoint descriptor becomes ready. `stop` verifies endpoint/authority/control identity, sends the exact credential to the verified loopback daemon, and does not report success until the target process, endpoint, control record, and authority are all gone. Public health/status never exposes the control credential.

The runtime data root is physically canonicalized, must be outside the source checkout, must be owned by the current user, and must not grant group or other access. Private security files are opened with no-follow semantics and validated by file descriptor metadata. Foundation JSON publications use private temporary files and atomic replacement.

Project registration is explicit. Input paths must be absolute, contain no NUL byte, resolve through `realpath`, and identify an existing non-root directory. `/Users/bill/iris-native-runtime` is a permanent read-only reference and literal mutation targets under it are denied before filesystem inspection.

Permission decisions are daemon-authoritative. Every exposed mutation passes through the capability registry, live client/session/project validation, physical target validation, permission policy, and local audit before execution. Unknown and unimplemented capabilities fail closed. `FULL_LOCAL_OWNER` automatically allows only implemented LOW/MODERATE operations that remain inside the effective approved project/runtime scope. HIGH and SYSTEM actions require the owner.

Project file operations reject path traversal and symlink components, compare the requested project against the live session project, and revalidate immediately before execution. Execution is then anchored by the bundled macOS safety helper to the canonical project root, walking parent components relative to directory descriptors with no-follow semantics. Hard-linked file targets are rejected, and writes use same-directory temporary replacement with identity rechecks before publication. Policy-level path validation is not treated as execution authority.

Session current-project state is isolated in memory and read/update/delete routes require the owning `clientId`. Each session also carries `agentId`/role attribution; permission audit derives the effective agent from the live owned session rather than trusting caller-supplied attribution. MCP uses the same session and permission engine as Web/API and cannot bypass the policy layer.

Permission audit remains local and records metadata only; it does not record file contents, API keys, passwords, tokens, control credentials, or secret values. Permission settings are explicitly initialized to the owner-authorized development mode and missing/corrupt settings after initialization fail closed.

Production model access is daemon-only. The OpenAI credential is accepted only from the explicitly allowlisted local child environment and is never written into repository state, runtime health, approval text, authoritative conversation history, or Web state. The provider receives only the current bounded instruction plus minimal role/project-selected context; project names, filesystem paths, repository contents, permissions/audit state, MCP state, other sessions, and credentials are excluded. Provider/network/timeout/malformed-response diagnostics cross the existing executor failure sanitization boundary before they can reach normal product APIs or history.

The same macOS-account process boundary remains a deliberate V1.3 trust assumption: IRIS does not claim to isolate mutually hostile processes already running as the same OS user. Stronger per-process local authentication is future hardening, not an implicit V1.3 guarantee.
